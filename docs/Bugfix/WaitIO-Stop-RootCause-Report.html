WaitIO 被 Stop 中断后 Group 异常完成 — 根因分析报告

📋 Bug 分析 📄 涉及模块：WaitIO / CalcTime / MotionEngine.Stop / HomeTask 📅 2026-04-23

一、问题描述

现象：在回零站(HomeStation)中，有一个 Group 负责机器人回零，步骤为"设置 IO 信号 → WaitIO 等待完成信号"。第一次 Home 执行到 WaitIO 等待时，用户手动触发 MotionController.Stop；第二次再执行 Home 时，该 Group 直接完成，但机器人实际并未完成回零。

三、根因分析（方案一）

3.1 核心缺陷：CalcTime 无法区分"条件满足"和"被中断"

问题：CalcTime 有两种退出路径（IsBreak 中断 / 条件满足），但它们的行为完全相同 —— 都是 break 退出循环后正常返回。调用者无法区分到底是因为 IO 条件满足了，还是因为被 Stop 中断了。

3.2 缺陷传导：WaitIO.DoExcute 将中断误报为成功

3.4 第二次 Home 异常完成的原因

第一次 Home 被 Stop 中断后的残留状态：
  • 所有模块 Status = Success（因为 WaitIO 误报成功导致整条链路都标记为成功）
  • IO 信号仍为第一次设置的值（Stop 未清除 IO 输出信号）
  • 模块 IsBreak = true（Stop 设置，Home 失败未重置）

第二次 Home 执行时：

  1. Home() 的 this.ForEach 设置 IsBreak = true（已经是 true）
  2. SetModuleBreak(homeStation, false) 正确重置 IsBreak
  3. homeStation.DoFunction() 执行 → 各子模块 DoFunction 重置 Status = Running
  4. Group 子模块重新执行：
    • SetIO 步骤执行：IO 信号已经是目标值（第一次残留），相当于空操作
    • WaitIO 步骤执行：检查 IO 值 → IO 条件可能已经满足（残留状态）→ action.Invoke() 立即返回 true
  5. WaitIO 立即完成 → Group 立即完成 → 但机器人实际未完成回零
根本原因总结：CalcTime 无法区分"IO 条件自然满足"和"被 Stop 中断强制退出"，导致 WaitIO 将中断误报为成功。第一次的误报使 IO 信号和模块状态残留，第二次执行时 WaitIO 检测到残留的 IO 值立即返回成功，Group "直接完成"而机器人并未实际回零。

四、修复方案

4.1 方案一（推荐）：WaitIO 检测 IsBreak 中断

在 WaitIO.DoExcute 中，io.WaitIO() 返回后检查设备是否被中断，而非正常完成：

WaitIO.cs — DoExcute 修复
✓ 修复代码
public override bool DoExcute(out string errMsg)
{
    GetVDevice<VIO>(Device, out var io);
    Result = true;

    /* ... retryAction 设置 ... */

    try
    {
        if (IOType == IOType.Digital)
            io.WaitIO(DigitalVal, OverTime * 1000, retryAction);
        else
            io.WaitIO(AnlogVal, OverTime * 1000, retryAction);

        // 检查 WaitIO 是否因 IsBreak 中断退出，而非 IO 条件满足
        if (io.IsBreak)
        {
            errMsg = $"{MyOwner.Alias} WaitIO 被中断";
            Result = false;
            return false;
        }
    }
    catch (DeviceTimeoutException dte)
    {
        /* ... 超时处理不变 ... */
    }

    return base.DoExcute(out errMsg);
}

修复原理：

  • CalcTime 退出后，如果 IsBreak == true，说明是被 Stop 强制中断，而非 IO 条件满足
  • 此时 WaitIO 应返回 false（失败），而非 true（成功）
  • 这会导致 Group 执行失败 → HomeStation 报告失败 → 第二次 Home 时 Group 会从头重新执行

4.2 补充方案：CalcTime 增加中断标志

如果希望从底层彻底解决，可让 CalcTime 区分退出原因：

VirtualDeviceBase.cs — CalcTime 增加返回值
✓ 补充修复
protected bool CalcTime(Func<bool> action, int timeout = -1, int sleep = 5, Action timeoutAction = null)
{
    double time = 0;
    IsBreak = false;
    IsPause = false;

    while (true)
    {
        WaitRecovery();
        if (IsBreak) return false;    // ← 中断退出，返回 false
        if (timeout > 0 && time > timeout) { /* ... */ }
        if (action.Invoke()) return true; // ← 条件满足，返回 true
        Thread.Sleep(sleep);
        if (!IsPause) time += sleep;
    }
}

此方案需要同步修改所有调用 CalcTime 的地方（VIO.WaitIO、VAxis 相关方法等），影响范围较大，建议作为后续优化。

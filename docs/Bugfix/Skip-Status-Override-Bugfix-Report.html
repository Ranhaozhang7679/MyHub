⚠ 问题描述

用户将工站内的子模块（如"设置变量"模块）设为忽略（Skip）后，设备在 Running 自动运行状态下，左键单击该忽略模块后，忽略状态被意外取消，模块直接执行并报错变红。

正常自动运行时 Skip 状态不会被取消，只有在流程图界面左键单击或拖动忽略模块后才出现。拖动动作比单击耗时更长，增大了与引擎自动运行循环的竞态窗口，因此触发概率更高。

🔎 根因分析

发现两处 Skip 保护缺失，在竞态时序下共同导致忽略状态被取消：

1 MotionModule.DoFunction() 缺少 Skip 检查

MotionModule.cs : 272 修复前 
public override bool DoFunction()
{
    // 没有 Skip 检查！直接进入执行流程
    ThreadID = Thread.CurrentThread.ManagedThreadId;
    if (IsBreak) { ... return true; }
    ...
    Status = RunStatus.Running;  // Skip 状态被覆盖为 Running
    ...
}

基类 AbsModule.DoFunction() 有 if (Status == RunStatus.Skip) return true; 保护， 但 MotionModule 重写后丢失了这个检查。一旦 DoFunction 被调用，Skip 状态就被强制覆盖为 Running。

2 SetModuleStatus 缺少顶层 Skip 保护

MotionEngine_part2.cs : 834 修复前 
private void SetModuleStatus(IMotionModule motionModule, RunStatus status)
{
    motionModule.Status = status;  // 顶层模块没有 Skip 检查
    if (motionModule.Children.Count > 0)
    {
        foreach (var item in motionModule.Children)
        {
            if (item.Status == RunStatus.Skip) continue;  // 子模块有保护
            ...
        }
    }
}

▶ 触发时序

  1. 用户将子模块设为忽略（Status = Skip）
  2. 设备进入 Running，引擎循环执行工站
  3. 用户在流程图界面左键单击或拖动该忽略模块（仅选中/移动操作，不涉及状态变更）
  4. 拖动操作比单击耗时更长，正好增大了与引擎自动循环的竞态窗口
  5. 引擎循环恰好运行到该工站，调用 SetModuleStatus(station, Default)
  6. 若存在竞态窗口，模块的 Skip 状态未能被 MotionRunEngine.Run 的检查拦截
  7. MotionModule.DoFunction() 被调用 — 没有 Skip 检查 → 状态变为 Running → 执行失败 → 变红报错

为什么拖动更容易触发？单击操作瞬间完成（MouseDown → MouseUp），竞态窗口极小。而拖动操作（MouseDown → MouseMove → ... → MouseUp）持续时间更长，与引擎后台线程的 SetModuleStatus 调用产生时间重叠的概率显著增加。

🔧 修复方案

1 MotionModule.DoFunction() 添加 Skip 检查

✗ 修复前
public override bool DoFunction()
{
    ThreadID = Thread.CurrentThread
        .ManagedThreadId;
    if (IsBreak) ...
    ...
    Status = RunStatus.Running;
}
✓ 修复后
public override bool DoFunction()
{
    // 忽略状态不执行
    if (Status == RunStatus.Skip)
        return true;
    ThreadID = Thread.CurrentThread
        .ManagedThreadId;
    if (IsBreak) ...
    ...
    Status = RunStatus.Running;
}

2 SetModuleStatus 添加顶层 Skip 保护

✗ 修复前
private void SetModuleStatus(...)
{
    motionModule.Status = status;
    if (motionModule.Children.Count > 0)
    {
        foreach (var item in ...)
        {
            if (item.Status == Skip)
                continue;
            ...
        }
    }
}
✓ 修复后
private void SetModuleStatus(...)
{
    // 忽略状态的模块不重置
    if (motionModule.Status == Skip)
        return;
    motionModule.Status = status;
    if (motionModule.Children.Count > 0)
    {
        foreach (var item in ...)
        {
            if (item.Status == Skip)
                continue;
            ...
        }
    }
}

🛠 修复影响

双重保护： 即使 SetModuleStatus 在竞态时序下未能拦截，MotionModule.DoFunction() 入口处的 Skip 检查也能作为最后防线， 确保 Skip 状态的模块永远不会被执行。两层保护互为兜底。

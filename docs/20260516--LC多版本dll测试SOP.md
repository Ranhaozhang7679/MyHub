# LC 轴卡多版本 DLL 测试 SOP

> 日期：2026-05-16
> 适用：LC 轴卡 DLL 多版本自动切换与版本管控功能

---

## 背景

LC 轴卡存在多个版本的 `ecat_motion.dll`，不同固件版本需要对应不同的 DLL。版本管控系统通过 `lc_version_config.json` 配置文件管理多版本 DLL 的加载与匹配。

**核心匹配逻辑**：软件加载 DLL 后，读取板卡的 FPGA 版本，与配置中的 `ExpectedFpgaVersion` 比对，判断当前 DLL 是否正确。

**现场测试前必须确认**：配置中 `ExpectedFpgaVersion` 字段已填入真实值（不能为空），否则所有版本都会匹配失败。

---

## 第一阶段：采集真实版本信息

**目的**：用正常工作的机台把 ExpectedFpgaVersion 填入配置。

### 步骤

1. 在一台能正常连接 LC 轴卡的机台上运行 `LCVersionCollector.exe`
2. 输入卡号（默认0），点击 **"连接并读取"**
3. 确认界面上显示了 DLL版本、FPGA版本、DSP版本
4. **记录这三个值**（拍照或手抄），后面验证时用
5. 填写版本ID（如 `v427`），点击 **"保存到配置"**
6. 打开 `lc_version_config.json`，确认对应条目的 `ExpectedFpgaVersion` **已填入值**（不再是空字符串 `""`）

> 如果有多种型号的板卡（不同固件版本），每台都要采集一次，每个版本ID对应一个条目。

### 采集后配置示例

```json
{
  "ActiveVersion": "v427",
  "Versions": [
    {
      "Id": "v427",
      "DllSubPath": "LC/DLLs/v427/ecat_motion.dll",
      "Description": "旧版DLL",
      "ExpectedDllVersion": "1.0 V4.27",
      "ExpectedFpgaVersion": "2.1 V4.27",
      "ExpectedDspVersion": "3.0 V4.27"
    }
  ]
}
```

---

## 第二阶段：验证版本匹配

### 测试1：正确配置 → 设备应正常上线

1. 确认 `ActiveVersion` 指向刚采集的版本ID
2. 确认 `ExpectedFpgaVersion` 不为空且值正确
3. 启动主程序，初始化 LC 轴卡
4. **预期结果**：
   - 设备正常 Online
   - 日志输出（Info级别）：
     ```
     LC板卡版本详情: 已加载DLL=v427(旧版DLL), DLL版本=1.0 V4.27, FPGA版本=2.1 V4.27, DSP版本=3.0 V4.27, 授权=xxx, 自动匹配=v427, 匹配结果=一致
     ```

### 测试2：ExpectedFpgaVersion 为空 → 应阻止运行

1. 把刚采集的条目的 `ExpectedFpgaVersion` 改回空字符串 `""`
2. 重启主程序
3. **预期结果**：
   - 日志输出（Info级别）：`匹配结果=不一致`
   - 日志输出（Error级别）：`LC板卡版本不匹配！...未在配置中找到匹配的固件版本`
   - 抛出 DeviceException，全局异常捕获弹窗提示
   - 设备 **不进入 Online**，保持 Offline

### 测试3：ExpectedFpgaVersion 故意写错 → 应阻止运行

1. 把 `ExpectedFpgaVersion` 改成一个不存在的值（如 `"9.9 WRONG"`）
2. 重启主程序
3. **预期结果**：同测试2，匹配失败，弹窗提示，设备保持 Offline

### 测试4：ActiveVersion 指向错误版本 → 应阻止运行并自动修正

> 此测试需要配置中有至少两个条目，且 ExpectedFpgaVersion 都已填入。

1. 把 `ActiveVersion` 设为一个与当前板卡不匹配的版本ID
2. 重启主程序
3. **预期结果**：
   - 日志输出：`匹配结果=不一致`
   - 日志输出：`固件匹配=xxx，当前加载不匹配，已自动更新配置 ActiveVersion=xxx，请重启软件`
   - 抛出 DeviceException 弹窗
   - 设备保持 Offline
4. 检查 `lc_version_config.json`，确认 `ActiveVersion` 已被自动更新为正确值
5. 再次重启主程序
6. **预期结果**：设备正常 Online，匹配结果=一致

### 测试5：ActiveVersion=auto → 自动探测

1. 把 `ActiveVersion` 改为 `"auto"`
2. 确保 ExpectedFpgaVersion 已正确填写
3. 重启主程序
4. **预期结果**：
   - 软件用 Versions[0] 的 DLL 作为探测
   - 如果 FPGA 匹配的就是第一个条目 → 直接 Online，匹配结果=一致
   - 如果 FPGA 匹配的不是第一个条目 → 弹窗提示需要重启，自动更新 ActiveVersion

## 检查清单

| 检查项 | 确认方式 | 通过标准 |
|--------|---------|---------|
| 日志中有"LC板卡版本详情" | 查看 Info 日志 | 一行完整输出 |
| 已加载DLL、DLL版本、FPGA版本、DSP版本都有值 | 日志中字段非空 | 非空且非"(未知)" |
| ExpectedFpgaVersion 不为空 | 打开 lc_version_config.json 检查 | 有实际版本号 |
| 匹配失败时弹窗+设备 Offline | 主程序界面+日志 | 弹窗出现，设备不进入 Online |
| 匹配成功时设备 Online | 主程序界面 | 设备状态为 Online |
| 自动更新 ActiveVersion | 测试4后检查配置文件 | ActiveVersion 已变为正确值 |

## 常见问题

**Q：现场所有板卡都是同一型号，是否只需要一个版本条目？**
A：是的。只要 FPGA 版本一致，一个条目就够了。`ActiveVersion` 固定指向该条目即可，不需要 auto 模式。

**Q：ExpectedFpgaVersion 为空时软件能正常用吗？**
A：不能。空值意味着无法匹配，软件会阻止运行。必须先用 LCVersionCollector 采集并填入。

**Q：auto 模式和手动模式怎么选？**
A：现场只有一种板卡型号 → 用手动模式（`ActiveVersion="v427"`）。现场有多种板卡型号需要自动切换 → 用 auto 模式。

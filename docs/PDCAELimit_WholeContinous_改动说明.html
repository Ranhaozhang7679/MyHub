PDCAELimit 功能改动说明 — WholeContinous 模式

日期：2026-05-20  |  分支：develop  |  改动文件：2 个

1. 背景与问题

现场反馈 PDCAELimit 的 Whole 模式在运行时，偶发 PDCA 服务端异常导致上传失败。

根本原因

Whole 模式将一次完整的 PDCA 流程拆分为 3 步串行操作，每步是独立的 TCP 事务：

步骤操作TCP 交互
①发送 Start 命令Write → Read（等返回）
②拷贝图片到 MacMini 网盘文件操作（可能耗时数秒）
③发送 Data + SubmitWrite → Read（等返回）
问题：步骤 ① 和步骤 ③ 是两次独立的 TCP 通信。当步骤 ②（图片拷贝）耗时长时，PDCA 服务端因长时间未收到完整事务（Submit），会话超时导致步骤 ③ 失败。

参考其他项目（BABI）的实现，其做法是将 start + attr + data + submit 全部拼在一条 _{} 批量消息里一次性发送，一个 TCP 事务完成全部操作，不存在中间间隔。

2. 改动方案

核心思路：新增 WholeContinous（打包上传）模式，将 Start、Attr、Data、Submit 合并为一次 _{} 批量发送。
保持现有 Whole 模式不变，向后兼容，现有产线无需修改配置。

改动文件清单

文件改动类型说明
PDCAELimit.cs 新增 新增枚举值、case 分支、批量消息拼接方法
SFCHelper.cs 修复 修复 SendPDCAData 缺少连接检查和超时参数未生效的问题

3. 详细改动

3.1 PDCAELimit.cs

① 新增枚举值 PDCAType.WholeContinous

public enum PDCAType
{
    Start,
    GetWIP,
    CopyImage,
    SendData,
    Whole,
    End,
    CCTV,
    WholeContinous  // 打包上传
}

② 新增 WholeContinous case（DoExcute 中）

执行流程：

  1. 异步拷贝图片（非 CPK/GRR 模式时，fire-and-forget，不阻塞主流程）
  2. 拼接完整批量消息 — 调用 GetSendDataContinuous 将 start + attr + data + submit 合为一条 _{}
  3. 压力值异常检测（force@-1@ 时跳过上传）
  4. 一次性 TCP 发送 — 调用 SendPDCAData 发送完整批量消息

③ 新增 GetSendDataContinuous 方法

生成的消息格式如下：

_{
    {WIP}@start[@audit]
    {WIP}@attr@Machine SN@{MachineSN}
    {WIP}@attr@CG SN@{SN}
    {WIP}@attr@Carrier SN@{CarrierSN}
    [{WIP}@attr@CG Display_SN@{DisplaySN}]    // 启用时包含
    {WIP}@pdata@{过程数据项1}
    {WIP}@pdata@{过程数据项2}
    ...
    {WIP}@pdata@Mode@{mode}
    {WIP}@pdata@Operator_ID@1
    {WIP}@pdata@Priority@{priority}
    {WIP}@pdata@TestSeriesID@{testSeriesID}
    {WIP}@submit@{软件版本}
}

3.2 SFCHelper.cs — 修复 SendPDCAData

SendPDCAData 方法存在两个已知问题，一并修复：

问题修复
发送前未检查连接状态 在 lock 块内添加 vComm.ConnectOK()
timeOutMs 参数未使用，硬编码 3000ms 改为 vComm.ReadSingle<string>("", timeOutMs) 
lock (lockPDCA)
{
    // 0.发送前检查连接状态
    vComm.ConnectOK();

    // 1.发送请求
    vComm.Write(startCmd);

    // 2.接收数据
    result = vComm.ReadSingle<string>("", 3000);
    result = vComm.ReadSingle<string>("", timeOutMs);
}

4. Whole vs WholeContinous 对比

对比项Whole（原有）WholeContinous（新增）
TCP 交互次数2 次（Start + Submit 分开发送）1 次（批量发送）
中间间隔有（图片拷贝在两次 TCP 之间）无
图片拷贝异步，不阻塞 TCP 发送异步，不阻塞 TCP 发送
服务端超时风险存在（拷贝耗时长时）不存在
消息格式Start 单发 + _{data+submit}_{start+attr+data+submit} 一条
向后兼容✅ 现有 Whole 模式完全不变

5. 使用方式

在流程编辑器中，将 PDCAELimit 模块的 动作类型 从 所有动作 改为 打包上传 即可。

其余参数（SN、WIP长度、图片路径、过程数据等）与 Whole 模式完全一致，无需额外配置。

6. 注意事项

  • 图片拷贝为异步操作，其失败不会阻塞数据上传流程，但会有日志记录
  • IsManual（手动输入 AELimits）模式下不支持 WholeContinous，该模式会走原有的数据拼接逻辑
  • CPK/GRR 模式下不拷贝图片，行为与 Whole 模式一致
  • 如果 PDCA 服务端不支持 _{} 批量格式，请继续使用 Whole 模式

1. 现场背景

机台初始状态：自动运行中（Running + Auto）

日志发生前，设备处于自动运行状态。事件链顺序：

  1. 设备自动运行中 → 先产生"红灯开始闪烁"（22.6302s）—— 报警触发
  2. 约 145ms 后 → ManualSwitchButton IO 读到"手动"信号（22.7758s）—— 非人为操作，疑为 IO 信号抖动/干扰
  3. IO 误读触发 Pause(false)（22.7868s）—— 覆盖了报警 Pause

确认根因：场景 A — 报警与 IO 误读的竞态条件

手动/自动切换按钮未被人为操作，MachineMonitor 读到的信号变化大概率来自 IO 线路的电磁干扰或信号抖动。报警正在异步处理中，EngineStatus 尚未更新为 Alarm，此时 IO 误读恰好通过状态检查，触发 Pause(false) 覆盖了报警流程。

4. 两种可能的场景分析

"红灯开始闪烁"的来源有两种可能，对应完全不同的场景。

结合现场背景（设备在自动运行中），场景 B 为确认根因。场景 A 作为结构风险保留供参考。

场景 A：红灯来自真正的报警 Pause(true)

可能性：中

调用链路

某处触发报警
↓
Pause(isAlarm: true)
↓
MotionEngine.Pause(true, callback)
Task.Run 异步
↓
回调执行: PauseLight(true)
→ "红灯开始闪烁" 22.6302s
↓ 回调继续
lockCommand 归零 (0)
↓ 回调结束
⚠ EngineStatus 尚未设置为 Alarm！
↓ MachineMonitor 轮询命中
检测到手动开关变化
↓
MachineStatus != Alarm → 条件通过
↓
Pause(false) 触发 → lockCommand=0 → 执行成功
↓
EngineStatus = Pause（非 Alarm）→ 状态不一致

关键代码 — MotionEngine.Pause() 的时序问题

// MotionEngine_part2.cs:597-608
finally
{
    LoadingEvent(total, total, "暂停完成");
    action?.Invoke(isSuccess, caughtEx);   // ① 回调执行
    //   ├─ PauseLight(true) → "红灯开始闪烁"  (22.6302s)
    //   └─ lockCommand → 0                     (释放锁)
}

// ← ⚠ 竞态窗口：lockCommand=0，但 EngineStatus 未更新

if (isSuccess)
{
    EngineStatus = isAlarm ? EngineStatus.Alarm : EngineStatus.Pause;  // ② 状态在此才设置
}

竞态条件：在 ① 回调完成到 ② 状态设置之间，存在一个时间窗口：

  • lockCommand 已归零 → 其他操作可以获取锁
  • EngineStatus 还不是 Alarm → 状态检查可以通过

如果 MachineMonitor 恰好在这个窗口内检测到手动开关变化，就会触发 Pause(false)，导致机台进入 Pause 状态而非 Alarm 状态。

后果：红灯闪烁但系统认为是普通暂停，恢复时执行 Resume 而非 Reset，报警信息可能未被正确处理。

6. 问题汇总与修复建议

问题 1：手动切换误亮红灯（确定性问题）

确定性 Bug

现象：手动/自动切换到手动时，三色灯亮红灯闪烁（与报警灯一致），操作员无法区分是"手动切换"还是"报警"。

原因：_lightManager.PauseLight() 默认参数 isException=true，触发红灯。手动切换应亮黄灯。

修复：

// MotionController.cs:1800 if (MachineStatus == EngineStatus.Running) { _lightManager.PauseLight(); // isException=true → 红灯 _lightManager.PauseLight(false); // isException=false → 黄灯 }

问题 2：MotionEngine.Pause() 状态设置时序（结构风险）

竞态风险

现象：报警 Pause 的回调执行完毕后，EngineStatus 才被设置。在回调返回和状态设置之间存在竞态窗口。

风险链路：

报警 Pause(true) 回调完成
↓
lockCommand → 0（锁释放）
↓ 但 EngineStatus 还是旧值
⚠ 竞态窗口
↓ 若此时 MachineMonitor 检测到其他事件
Pause(false) 可以获取锁并通过状态检查
↓
EngineStatus = Pause 覆盖 Alarm

修复建议：将状态设置移到回调之前，确保 EngineStatus 先更新，再释放 lockCommand：

// MotionEngine_part2.cs Pause() 方法末尾 finally { LoadingEvent(total, total, "暂停完成"); action?.Invoke(isSuccess, caughtEx); // 回调在前 } if (isSuccess) { EngineStatus = isAlarm ? Alarm : Pause; // 状态在后 }

注意：此项修改需要评估回调中的 PauseLight、lockCommand 释放等逻辑是否依赖状态更新顺序，建议充分测试后再上线。

问题 3：日志无法区分报警与手动切换（可观测性问题）

可观测性

现象：无论是报警还是手动切换，日志都记录 "红灯开始闪烁"，无法区分来源。

建议：在 LightManager 中增加来源标识，或在 MotionController 的调用处添加上下文日志：

// MotionController.cs:1798-1801 if (MachineStatus == EngineStatus.Running) { MotionEngine.OnLog(LogType.Info, "手动切换触发暂停灯"); _lightManager.PauseLight(false); }
